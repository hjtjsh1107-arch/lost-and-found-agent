# VLM 연결 조사 및 이미지 분석 검증

## 재현과 원인

조사 시점에 React의 `/api/health`는 `mode=mock`을 반환했다. FastAPI는 `.venv-real`의 Python 3.12.16으로 실행 중이었고, 루트 `.env`에 `APP_MODE=mock`이 설정되어 있었다. 같은 우산 PNG를 수정 전 API에 업로드하자 `기타 / 습득물 / 회색`과 `회색 물품을 보관하고 있습니다.`가 재현됐다. 사진은 디코딩됐고 `MockModels.extract()`의 첫 픽셀 기반 배경 추정과 형태·색상 규칙으로 처리됐다. 이 실행 경로에서는 VLM을 호출하지 않았다.

FastAPI의 `create_app()`은 모드에 따라 `MockModels` 또는 `OllamaModels`를 선택했다. 당시 PoC의 설정은 `qwen3-vl:4b`였고, `vlmtest.py`가 실제 요청한 모델은 `qwen3-vl:8b`였다. 로컬 Ollama의 모델 목록에서 후자를 확인했다. 사진을 첨부한 같은 단독 요청을 재현해 접이식 우산, 연회색 본체, 흰색 손잡이, 접힌 상태를 얻었다. 베이지색 조각의 용도나 우산에 부착되었는지는 이 사진에서 확정하기 어렵다.

기존 어댑터는 이미지를 Base64로 담아 같은 로컬 `/api/chat`에 전달했으나, 단독 요청과 달리 스키마 제약과 추론 설정을 추가했다. 8B로 기존 어댑터를 강제 실행했을 때도 예외가 재현됐다. 계측을 추가한 구조화 호출에서 Ollama는 HTTP 200으로 응답했지만 `message.content`는 빈 문자열이었다. 긴 JSON 강제 요청에서는 `done_reason=length`도 확인했다. 작은 요청에서는 JSON 및 스키마 모두 결과를 반환했다. 큰 출력 계약에서는 종료 예산을 소진할 수 있으며, 스키마 크기와 컨텍스트 각각의 영향은 분리 계측하지 않았다.

사진을 담은 단일 사용자 메시지에서 JSON 구조를 요청하자 출력 본문을 받았다. 그 응답은 부위별 색을 객체로, 부속품과 사진 근거를 배열로 반환했다. 이전 파서는 이 형태를 처리할 수 없었다. 실제 응답을 재생해 본체 색과 손잡이 색이 분리되고 부속품 값도 유지됨을 확인했다. 추출 요청의 한 장짜리 전체 사진 근거는 해당 사진에 연결하며, 여러 장일 때 모델이 제공한 유효한 필드별 근거만 유지한다.

## 수정 내역

| 파일 | 역할 |
| --- | --- |
| `backend/config.py`, `.env.example` | 기존 변수 이름을 사용해 실행 모드와 로컬 모델을 선택한다. 공식 분류 필수 게이트는 별도 플래그다. |
| `backend/models.py`, `backend/schemas.py` | 단독 테스트와 동일한 로컬 모델 및 이미지 요청을 사용한다. 사진 분석에서는 모델에 JSON 형식을 요청하고 응답의 관찰 값을 정규화한 뒤 Pydantic으로 검증한다. 물품 유형, 부위별 색, 손잡이, 무늬, 부속품을 분리한다. 모델 미설치, 이미지 입력, 연결 및 파싱 오류를 구분한다. |
| `backend/categories.py` | 관찰한 이름·유형·속성과 공식 분류 코드 및 매핑 상태를 구분한다. 두 단계가 정확히 매핑된 경우만 `mapped`를 반환한다. |
| `backend/workflow.py`, `backend/privacy.py`, `backend/service.py` | 추정과 불일치는 근거에 남긴다. 공개 후보를 심사한 뒤 검증 결과와 결합해 제목·설명을 만든다. 복수 단계에서 승인 및 공식 분류 조건을 확인한다. |
| `backend/model_diagnostics.py`, `scripts/inspect_vlm.py` | 일반 로그와 개인정보 없는 테스트 사진의 원본 응답 진단을 분리한다. 원문 진단은 명시한 테스트 사진으로 로컬에서 다시 실행한다. |
| React 분석·실행 로그 화면 | 모드와 오류, 매핑 상태, 모델 호출 여부·전송 성공 여부·소요 시간·필드 및 검증 건수를 확인할 수 있다. |

기존 LangGraph 단계와 데이터베이스 테이블 구조를 재사용했다. VLM 호출 실패는 상태 및 오류 코드로 남긴다. 기본 PoC 게시 모드는 미매핑 관찰 정보를 보존한다. 정식 분류 필수 모드는 `REQUIRE_OFFICIAL_CATEGORY=true`로 켠다.

## 같은 우산 사진 비교

2026-11-24 로컬 검증에서는 당시 로컬 진단 스크립트에 지정된 사진을 사용했다. 현재 저장소의 재현 절차는 `scripts/inspect_vlm.py`를 사용한다.

| 항목 | 수정 전 PoC API | 단독 VLM 요청 | 수정 후 React Real Mode |
| --- | --- | --- | --- |
| 실제 호출 | 없음, Mock | `qwen3-vl:8b` | 추출·검증에 `qwen3-vl:8b`, 공개 심사에도 같은 로컬 모델 |
| 물품명 / 유형 | 습득물 / 기타 | 우산 / 접이식 우산 | 우산 / 접이식 |
| 색상 | 회색 | 본체 연회색, 손잡이 흰색 | 본체 베이지, 손잡이 흰색 |
| 형태 및 손잡이 | 미확인 | 접힌 상태, 곡선형 및 구멍으로 판단 | 접혀진 상태, 링 모양 |
| 기타 특징 | 미확인 | 검정 밴드와 베이지색 조각을 언급 | 단색으로 분류하고 베이지색 조각을 케이스로 추정. 부속품은 공개 문구에서 제외 |
| 공식 분류 | 매핑 로직 없음 | 해당 없음 | 대·소분류 미확정, `unmapped` |
| 공고 제목 | 습득물 습득 | 해당 없음 | 베이지 접이식 우산 습득 |
| 공개 설명 | 회색 물품을 보관하고 있습니다. | 해당 없음 | 베이지 접이식 우산입니다. 확인된 형태는 ‘접혀진 상태’입니다. 손잡이 색상은 흰색입니다. |
| 전체 처리 시간 | 0.108초 | 54.64초 | 210.4초 |

React 검증에서 OCR 영역은 0개, 추출된 필드는 11개였다. 분석은 공고 검토 상태에 도달했다. 브라우저의 경과 시간에는 모델 대기 및 에이전트 실행 시간이 포함됐다. 동일 사진의 본체 색이 단독 요청과 수정 후 PoC에서 달랐으며, 회색 계열과 베이지 계열의 경계는 담당자 재확인이 필요하다. 외관이 비슷한 물품을 구별하는 기준이나 색상 판정의 정확도는 한 사진으로 일반화할 수 없다.

추가 전구 일러스트를 React에서 올렸을 때 `qwen3-vl:8b`가 전구의 이름과 10개 필드를 추출했다. 8B 사진 검증은 두 번 모두 출력 한도에서 종료되어 초안을 보류했다. 검증 모델을 `qwen3.5:9b`로 분리한 뒤 같은 사진과 저장된 추출값을 브라우저에서 재검증했다. 전구는 43.7초 만에 일부 정보 확인 상태로 공고 검토에 도달했다. 공고 제목은 `전구 습득`이며 검증되지 않은 색과 특징은 공개 설명에서 제외됐다. 우산은 26.9초의 재검증을 거쳐 앞서 확인한 제목과 설명을 유지했다. 두 재검증 시간에는 초기 사진 업로드나 8B 추출이 포함되지 않는다.

## 다시 실행

로컬 Ollama를 먼저 실행하고 `ollama list`에서 `qwen3-vl:8b`와 `qwen3.5:9b`를 확인한다. 이 PC의 `.env`는 추출에 8B, 사진 검증과 공개 심사에 9B를 사용한다. Real Mode는 별도 로컬 SQLite DB를 사용한다. PostgreSQL에서 실행하려면 준비된 Real DB의 `DATABASE_URL`을 지정한다. 담당자 접속에는 `.env`의 `STAFF_TOKEN`을 사용한다.

```powershell
.\start.ps1 -PythonPath .\.venv-real\Scripts\python.exe -BackendPort 18000
```

정규화, 미매핑, OCR 미검출 및 오류, 검증 거부, Ollama 연결 실패·모델 미설치·구조화 실패를 포함한 API 테스트 22개(PostgreSQL 포함)와 Chrome Mock E2E 3개가 통과했다. 응답하지 않는 로컬 포트와 실제 Ollama의 미설치 모델을 각각 호출해 연결 오류와 모델 미설치 오류가 구분되는 것도 확인했다. 프론트엔드 생산 빌드가 통과했다.
